# Інструкція для AI-агента, який продовжує роботу над цим ботом

Telegram-бот "invest-bot": підказує, коли і якими лімітними ордерами докуповувати
BTC/ETH, стежить за earn-пропозиціями на біржах, бюджетом, ETF на IBKR. Повну
концепцію, зафіксовані рішення й історію змін — дивись **`invest-bot-concept.md`**
у корені репозиторію. Цей файл — лише про те, ЯК тут вносити зміни.

## Мова і стиль

- Код, коментарі, docstrings, тексти для користувача — **українською**.
- Коментарі пояснюють **чому** так зроблено (рішення, пороги, межі), а не що
  робить код рядок за рядком. Дивись існуючі docstrings модулів як приклад тону.
- Мінімум жаргону в текстах, які бачить користувачка в Telegram.
- Дані для прикладів, тести — реалістичні: справжні назви бірж, монет, сум.

## Структура `app/`

- `handlers.py` — команди Telegram.
- `alerts.py` — планувальник: алерти про хорошій момент, earn-сповіщення, чистка застряглих ордерів.
- `engine.py` — движок рішень: оцінка "дешево/дорого", розподіл BTC/ETH, драбинка ордерів.
- `advisor.py` — AI-трейдер на Google Gemini (опційний, працює без ключа теж).
- `earn.py` — earn-пропозиції з OKX/Bybit.
- `portfolio.py` — реальні залишки на біржах (read-only ключі).
- `income.py` / `journal.py` — облік заробітку й журнал earn-вкладів (чого API не віддає).
- `budget.py` — місячний бюджет DCA.
- `ibkr.py` — щомісячна купівля ETF.
- `status.py` — повний копіювальний дамп стану для стороннього AI-чату.
- `formatting.py` — усі тексти для Telegram, включно з `<pre>`/`<code>` tap-to-copy блоками.
- `market.py` — зовнішні джерела даних (CoinGecko, Fear&Greed).
- `storage.py` — SQLite: налаштування, журнал, стан алертів.
- `keyboards.py` — інлайн-клавіатури.
- `config.py` — конфіг з `.env`.

`.cursor/*.py` — одноразові діагностичні/smoke-скрипти для ручної перевірки
живих даних, не частина застосунку. Нові подібні скрипти теж туди, а не в `app/`.

## Тести — обов'язково перед тим, як сказати "готово"

```
./.venv/bin/python -m pytest -q
```

Венв уже є в репо (`.venv/`), системний `python`/`python3` може не мати pytest.
Якщо тест `test_budget_shows_what_is_actually_left_to_use` падає — він залежить
від поточної календарної дати (минулий місяць у бюджеті), це відома й
непов'язана з рештою змін проблема, не намагайся її "лагодити" заразом з іншим.

Кожна нова поведінка — новий тест поруч із релевантним (`tests/test_*.py`),
а не окремий `summary.md`/звіт.

## Секрети й дані

- `.env` — реальні токени/ключі, у `.gitignore`, НІКОЛИ не комітити.
- `.env.example` — шаблон без значень, можна й треба оновлювати при нових полях конфігу.
- Ключі бірж (OKX/Bybit) — тільки READ-ONLY, без торгівлі й виводу. Бот ніколи
  не торгує сам: ордери людина ставить руками, бот лише радить.
- `invest_bot.db` — локальна SQLite-база з реальними даними користувачки.
  У `.gitignore` (`*.db`), але файл уже трапляється в git-історії репо — якщо
  бачиш його зміненим у `git status`, НЕ стейджи й не комітуй цю зміну.

## Git-флоу

- Працюємо прямо в `main`, без форків/PR на цьому етапі.
- Перед комітом — прогнати тести (вище).
- Коміти — осмисленим повідомленням українською, що саме змінилось і чому.
- Пуш у `origin/main` — це пуш у захищену гілку; якщо інструмент про це
  попереджає, це очікувано, тому що user попросив явно запушити.

## Що НЕ робити

- Не генерувати `README.md`/`summary.md`/звітні файли — підсумки й пояснення
  давати в чаті.
- Нові файли, не пов'язані з тестовим покриттям (нові rules, скрипти,
  діагностика) — класти в `.cursor/`, а не розкидати по корені чи `app/`.
- Не вигадувати нових торгових ключів/можливостей автоторгівлі — це свідомо
  заборонена межа цього проєкту (див. `invest-bot-concept.md`, розділ 2).

## Робота з телефону (Cursor mobile / Cloud Agents)

Репозиторій живе на GitHub: `https://github.com/Daria144/temki_mytki` (ветка `main`).
Щоб продовжити роботу з телефону без відкритого лептопа:

1. Встанови застосунок **Cursor** на телефон і увійди тим самим акаунтом.
2. У розділі агентів вибери цей репозиторій (`Daria144/temki_mytki`) — Cursor
   клонує його у хмарне ізольоване середовище, цей файл (`AGENTS.md`) агент
   підхопить автоматично як контекст.
3. Пиши задачу звичайною мовою (українською) — агент бачить код, тести й цей
   файл з правилами.
4. Хмарний агент НЕ має `.env` з реальними токенами (він у `.gitignore` й не
   живе в GitHub) — для задач, де не потрібно запускати бота живим (зміни в
   коді, тексти, тести), це не проблема. Якщо колись знадобиться живий прогін
   з реальними ключами — це окрема розмова про безпеку, не через хмарного
   агента з телефону.
5. Результат агент або комітить і пушить сам (якщо дозволено), або готує
   diff/PR — залежно від налаштувань агента в застосунку.
